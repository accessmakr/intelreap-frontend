02 What an IP Address Is

An IP address (Internet Protocol address) is a number that identifies a network interface, such as a Wi-Fi or Ethernet adapter, and tells other devices where to send data to it. It does two jobs at once: part of it names the network, and the rest names the interface within that network. IPv4 addresses are defined in RFC 791, and the addressing rules for IPv6 in RFC 4291.

The split between network and device is set by the subnet mask. In 192.168.1.42 with the mask 255.255.255.0, the first three numbers name the network and the last names the device. That is why devices on one home network share their first numbers and differ only at the end.

An address belongs to an interface, not to a person. A laptop with both Wi-Fi and Ethernet has two addresses, one per interface, because RFC 4291 defines each unicast address as identifying an interface. Many people can also share one public address, so an IP address points to a connection, not to a person.

Some older guides describe address classes A, B and C. Classful addressing was replaced by CIDR in 1993 (RFC 1519, now RFC 4632), which is why this page uses a prefix length such as /24 instead.

03 Public vs Private IP Addresses

Your home has one public address from your ISP, and every phone, laptop and printer inside has a private one. A router running NAT (network address translation) rewrites a private address to the public one on the way out and keeps a table, so replies find their way back to the right device. NAT translates ports as well as addresses, which is how many devices share one address (RFC 3022).

Traditional NAT only opens sessions from the inside, so a private address is not reachable from the internet unless the router is told to forward traffic to it. Rule of thumb: an address starting 192.168, 10 or 172.16 to 172.31 is private, and if a website shows you a different address, that one is your public IP.

04 How Data Finds You

When you open a website, your device sends a packet addressed to the site's IP address, and the packet also carries your own address as the source. Each router on the way reads the destination, picks the next hop from its routing table and forwards the packet. No router needs a map of the whole internet, only the best next step for each destination. The reply is addressed back to the source, so the two addresses swap places.

The names you type become addresses first, because DNS looks the name up. If that lookup is slow, pages start late even on a fast connection: see how to fix a slow DNS lookup. Behind NAT, the source address your router sends is the public one, which is why replies return to the router.

05 How Do I Get to an IP Address?

To get to an IP address, type it into a browser's address bar like a web address, for example http://192.168.1.1, or test it with ping 192.168.1.1. What happens depends on the kind of address.

06 How a Device Gets Its Address: DHCP, Static and Dynamic

Most devices get their address automatically. A DHCP server, usually your router, lends one for a limited time called a lease. DHCP (RFC 2131) works in four messages: the device asks, the server offers an address, the device requests that address and the server confirms it. The device then asks to renew at about half the lease time.

A dynamic address can change when a lease expires or equipment restarts. A static address is set by hand on the device, or reserved on the router so it always hands out the same one, which suits printers and servers. Finding and keeping a printer's address shows a reservation in practice.

07 IPv4 vs IPv6 and How to Read an IPv6 Address

IPv4 has 232 addresses, about 4.3 billion. IANA handed its last free IPv4 blocks to the regional registries in 2011, which is why NAT is so common. IPv6, specified in RFC 8200, uses 128 bits, enough that NAT is not needed for scarcity.

IPv4 compared with IPv6
FeatureIPv4IPv6
Length32 bits128 bits
Written asFour decimal numbers: 192.0.2.1Eight hex groups: 2001:db8::1
Address countAbout 4.3 billionAbout 3.4 x 1038
Needs NATUsuallyNo
Private equivalent10/8, 172.16/12, 192.168/16fc00::/7 (unique local)

An IPv6 address is eight groups of four hexadecimal digits separated by colons. Two rules shorten it. Leading zeros in a group can be dropped, and one run of consecutive all-zero groups can be replaced by a double colon, once per address (RFC 4291). RFC 5952 recommends writing the shortest form in lowercase.

An IPv6 address also carries a prefix length such as /64. On most networks the first 64 bits identify the network and the last 64 identify the interface.

09 What Your IP Address Reveals

An IP address reveals your ISP, your network type and an approximate region. It does not reveal your name, street address or what you do online. Location comes from databases that estimate it, so it can point to the wrong city, especially on mobile networks and VPNs. To see how your connection is classified, use the VPN and Proxy panel, and for lookups from the other side read what a reverse IP lookup is.

Every website you visit already receives your public address, so sharing it is normally low risk. A VPN replaces the address websites see with the VPN server's, though leaks such as WebRTC can still expose the real one. The WebRTC leak test checks for that.

10 Reading an Address: Subnet Masks and CIDR

An address always comes with a subnet mask, which says how much of it names the network and how much names the device. CIDR (RFC 4632) writes the number of network bits after a slash. 192.168.1.42/24 means the first 24 bits are the network.

Worked example. For 192.168.1.42 with mask 255.255.255.0 (/24), the address in binary is 11000000.10101000.00000001.00101010 and the mask is 24 ones followed by 8 zeros. Keeping the network bits gives the network 192.168.1.0. Usable device addresses run from .1 to .254, and .255 is the broadcast address. Two devices talk directly only if they share the same network part.

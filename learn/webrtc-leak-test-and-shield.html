Quick Answer

A VPN does not always cover WebRTC

WebRTC can reveal your real IP address even with a VPN on, when its request takes a route outside the VPN. The test below compares the public addresses WebRTC reveals with the address websites see. A different address means a leak if a VPN is on. The fix depends on your VPN type and browser.

02 Why WebRTC Can Reveal an Address Behind a VPN

WebRTC is the browser feature behind video calls and peer-to-peer connections. To connect two browsers it gathers candidate addresses: the device's own, and the address a STUN server reports after the connection passes through a NAT, which MDN calls a server reflexive candidate. A script on a web page can read those candidates, so a page can learn an address without a call ever starting.

When the VPN carries that request too, the address reported is the VPN's. RFC 8828 describes the cases where it does not: a device with more than one route, or a split-tunnel VPN, can reveal the ISP address; a device behind a NAT can reveal a private address; and STUN requests may go around a classical application proxy.

A VPN delivered as a browser extension works as a proxy for that browser's traffic, so the proxy case is the one that applies to it. A private address is a smaller matter. Chrome replaces it with a random mDNS name unless the page has camera or microphone access, as a Chrome developer announced, and WebKit says Safari exposes only server reflexive and relay addresses without that access. Public and private addresses are explained in What Is an IP Address?

03 How Browsers Limit What WebRTC Reveals

RFC 8828 defines four ways a browser can handle addresses, from revealing every address to forcing all traffic through a proxy. Each step reveals less and gives WebRTC fewer ways to connect.

Chrome and Edge name their four policy values default, default_public_and_private_interfaces, default_public_interface_only and disable_non_proxied_udp, which follow the same order. Brave offers matching choices in its settings, including Default, Default Public Interface Only and Disable Non-Proxied UDP.

04 Which Fix Fits Your Setup

Choose by how your VPN works, because the strictest option is not always the right one. The extension author's documentation says Disable non-proxied UDP effectively disables WebRTC for most users, and that default public interface only is the option meant for people on a system VPN.

05 Steps by Browser

Firefox

  1. Type about:config in the address bar and accept the warning.
  2. Search for media.peerconnection.enabled.
  3. Double-click it to set it to false.

That switches WebRTC off, so sites that use it for calls will stop working. For a milder change, set media.peerconnection.ice.default_address_only to true instead, then run the test again.

Brave

  1. Open the menu and choose Settings, then Privacy and security.
  2. Find WebRTC IP handling policy and pick an option.

Brave's help centre says most people do not need to change it. Use Default Public Interface Only on a system VPN, and Disable Non-Proxied UDP only with an extension VPN or proxy, accepting that calls may stop working.

Chrome and Edge

Chrome's Settings page has no WebRTC switch that we found in its documentation. Extensions can set the policy through the privacy API, and the WebRTC Leak Prevent extension documents the options it offers. Administrators can set a policy on managed browsers; Microsoft documents the Edge version. Without those, the practical fix on these browsers is a VPN that routes the browser's traffic through the tunnel.

Safari

We found no WebRTC setting for Safari. Without camera or microphone access it exposes only server reflexive and relay addresses.

06 VPN-Level Causes and Fixes

If a leak shows with a VPN app, check whether it offers split tunneling, because RFC 8828 names a split-tunnel VPN as a case that reveals the ISP address. Route the browser through the VPN and run the test again. If you use a VPN extension, expect the proxy case, and either set the browser option above or use a system VPN app. After any change, run the test again with the VPN on.

07 How to Turn WebRTC Back On

If calls stopped working after you changed a setting, undo it. In Firefox set media.peerconnection.enabled back to true. In Brave choose Default for the WebRTC IP handling policy. In Chrome, disable or remove the extension that set the policy, or ask your administrator to change a managed policy. Chrome, Edge, Firefox, Brave and Safari all include WebRTC, so nothing needs installing.

08 What the Test Cannot Tell You

This test looks only at WebRTC, from one browser, at one moment. It does not test for DNS leaks, and it cannot compare an address of the other family, so a VPN that does not handle IPv6 needs a separate check. A clean result also leaves other ways to recognise you, such as a browser fingerprint, which device fingerprinting explains. For the wider checklist, see how to protect your privacy online.

Logic

Separate three things that are often confused: a public address that differs from the one websites see (a leak with a VPN on), a private LAN address (not a VPN leak), and no address at all. Test the first directly, explain why it happens using the standard, then match the fix to the VPN type instead of recommending the strictest setting.

Methodology

The test runs in your browser. It opens a WebRTC connection to a public STUN server, reads the candidate addresses, classifies them, and compares public ones with the address IntelReap sees for your web request, only when they are the same address family. It stores nothing. We tested the logic in a real browser with simulated WebRTC and identity responses, not against real VPNs. That browser-extension VPNs fall under RFC 8828's proxy case is our reading, not stated by the RFC. The mapping of Chrome and Edge policy values to the four modes is our reading of their names. The WebKit post is from 2017, the Brave wiki page is archived and the Chrome mDNS notice is a developer announcement, so browser behaviour may have changed. We found no Chrome Settings option, which is not proof that none exists.
